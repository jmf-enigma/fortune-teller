# 八字专业裁决 v0.4

本文件描述 `src/core/bazi-adjudicator.mjs` 的独立专业裁决层。它建立在现有八字计算事实之上，不替代排盘，不把传统方法包装成已经验证的预测科学。

## 用户先看到什么

完整结果必须按以下顺序呈现：

1. `conclusion`：当前最重要的裁决；
2. `plain_language`：普通人能读懂的解释；
3. `basis`：实际使用的计算事实 ID；
4. `change_conditions`：出现什么新事实时必须改判；
5. `reality_checks`：怎样用连续、同期记录核对，而不是事后挑相似经历；
6. 需要复核时再展开 `competing_hypotheses`、各视角来源状态及未决项。

普通输出不应先显示哈希、规则包编号或内部审计字段。

## 调用方式

```js
import { calculate, adjudicateBazi } from "../../src/index.mjs";

const natal = calculate("bazi", {
  date: "2000-08-16",
  time: "04:00",
  timezone: "Asia/Shanghai",
  chart_sex: "male",
  target_date: "2026-08-24",
});

const result = adjudicateBazi(natal);
```

公开 CLI 可读取一份已计算的八字 envelope：

```bash
node scripts/fortune-teller.mjs adjudicate-bazi --input calculation.local.json --pretty
```

中文交互向导在“人生整体/一个方面 → 八字”路径中会询问大运顺逆所需的传统二元参数和目标日期，并先显示裁决，再显示四柱。`adjudicateBazi` 的机械输出已经公开；普通 reading schema 中的 `R-BZ-005/006` 在专用 typed binding 完成前只允许 `unresolved`，因此模型不能借登记规则自由改写格局或阶段结论。

## 设计原则

### 不做流派平均

旺衰、格局、扶抑、调候、通关和病药不是六个可以相加的指标。v0.4 为每个视角分别保存：

- 适用前提；
- 支持事实；
- 反对事实；
- 当前状态；
- 建议方向；
- 改判条件；
- 来源状态。

两个视角给出不同方向时先把“印星”等组名展开到正印/偏印等统一本体；有交集时记录交集，没有交集也只表示建议不同。只有某条登记规则明确声明互斥方向时才写入 `lenses.conflicts`。各视角始终保持并列，不投票、不平均、不偷偷指定一个“综合用神”。

### 不用伪精确分数

现有八字引擎把天干、地支和藏干计数分开保存，并明确禁止把它们合成未经登记的力量分。本裁决层继续遵守这条边界：

- 不设置藏干权重；
- 不设置旺衰百分比；
- 不用“达到多少分就是身强”；
- 不从五行缺失直接取用神；
- 不把流派结论转成平均分。

旺衰只检查具名条件的组合：月令本气、支中根位、可见生扶、可见克泄耗。条件相互冲突时，偏强与偏弱候选会同时保留。

## 旺衰：竞争假设

`lenses.strength.hypotheses` 固定保留：

- `H-BZ-STRENGTH-STRONG`：日主偏强候选；
- `H-BZ-STRENGTH-WEAK`：日主偏弱候选。

每条候选都包含 `supporting_evidence`、`contrary_evidence` 与 `change_conditions`。只有具名条件完整且没有直接冲突时，才进入“成立”。支持与压力并存时可以是“受损”或“未决”，不会为了方便取用而强制收敛。

当前范围仍是粗层裁决，不包含：

- 经逐条核对的人元司令分日；
- 透干通根的完整远近、真假和制化次序；
- 合而化、合而不化、冲而能动、冲而受制的完整状态机；
- 墓库、空亡、刑害对根气的流派化处理；
- 专旺、从势、从财、从杀、从儿和化气格的独立状态机。

所以本模块宁可保留未决，也不会用固定分数填补这些空白。

## 格局：成立、受损、破格、救应、未决

格局从月令本气建立候选，但“本气透出”本身不等于成格。当前状态机为：

```text
月令候选
  ├─ 命中一条已登记复合成格路线 → 成立
  │    ├─ 命中受损路线 → 受损
  │    │    ├─ 闭合受损路线且对应闭合救应齐全 → 救应
  │    │    ├─ 闭合受损路线且对应救应缺失 → 破格
  │    │    └─ 涉及轻重、位置或制化未闭合 → 只停在受损
  │    └─ 未见已登记破坏 → 成立
  └─ 复合成格条件不齐 → 未决
```

结果保留 `state_history`，因此“救应”不会抹掉之前确实存在的“受损”。

`BAZI_MONTH_COMMAND_PATTERN_RULES` 已把《子平真诠》第九章的成、败、救应拆成具名复合路线，但只安装当前 facts 能够直接核对的子集。当前只有“正官成格 → 官逢伤 → 透印解伤护官”具备自动走到破格/救应的闭合链。财轻比重、印轻逢财、位置妥贴、合煞是否清、合而能化等条件仍需轻重、位置和制化状态机，所以只作候选或 `screening_only`，绝不因见到一个十神便自动叫破格/救应。

## 五个取用视角

### 格局取用

只服务于已经建立的月令格局及其受损、救应链。格局破损时提出的是修复方向，不自动成为全盘唯一用神。

### 扶抑

只有旺衰候选明确成立后才给方向。旺衰未决时，扶抑必须同步未决。

### 调候

调候对版本和具体日干、月支条目敏感。当前规则包没有安装已经逐条核对的 120 条表，因此默认未决。调用方传入的 `source_status`、条目 ID 或喜用方向不能作为证据，也不会开启调候。未来只有把固定版本条目纳入可重放规则包并由程序按本盘日干、月支重新命中后，才会开放这一视角；开放后也只能独立并列，不能覆盖格局和扶抑。

### 通关

当前引擎没有证明“两强相战”和中介力量确实可用，所以默认未决。调用方自报两股力量、中介、来源状态或依据 ID 均不参与裁决；未来必须由可重放事实和登记 predicate 重新推出。不能看到两种五行就自动称为通关。

### 病药

病药视角必须先指明具体受损条件，再寻找对应救应。没有病点时不泛称某五行为药；有病无救时如实写“受损”，而不是编一个万能用神。

## 原局、大运、流年

时间层级固定为：

```text
原局 = 基线
大运 = 环境
流年 = 触发
```

八字引擎在明确出生时刻并显式提供 `chart_sex` 时，按固定上游算法计算顺逆、精确起运时刻和 24 步大运；提供 `target_date` 后还会计算目标日所在大运与以立春换年的年柱。裁决层优先读取这些可重放事实：

- `target.active_decadal_fact_id` 指向的 `decadal[]` 条目作为大运环境；
- `target.yearly` 作为流年触发；
- 目标日撞起运边界时，大运保持不可用；
- 目标日撞立春节气且年柱存在日内候选时，流年保持不可用；
- 只接受这份计算 envelope 内可重放的周期事实；外部 `periods` 无论怎样声称“已验证”都不会参与裁决。

目标层还会生成具名关系：天干重复、五合、冲、克；地支重复、自刑、六合、冲、害、破、刑；原局伏吟、岁运并临、天克地冲，以及运年补成三合/三会。普通“天干相克”或单独重复不会自动构成完整三层联系。兼容字段 `joint_activation` 当前只判断大运—原局、流年—原局，以及岁运之间或同一原局支点是否存在已登记的实质联系；它没有逐条重跑原局格局的成格、受损与救应条件，所以只能称“三层结构相连”，不能称格局联合引动，更不等于已经发生某件事。

如果计算结果没有目标日期周期事实，对应阶段直接不可用；调用方不能用另一份对象补写。时间层出现某个十神时只记录它可能补入哪条复合路线；必须把整条路线和原局重新核对，不能直接把它标为成格、破格或救应。

大运可以说明某一类条件在较长阶段更容易发挥，但不能修改原局格局状态；流年只作为触发，不得单独命名婚姻、财富、疾病、官非、事故等具体事件，也不得由某一年反推原局本来就“应该”是什么。

## 来源状态

规则包区分以下来源层级：

1. `SRC-BZ-LUNAR-TS-1.8.6`：只验证排盘字段的实现来源；
2. `SRC-BZ-SANMING-WIKISOURCE`：只提供四柱、十神及干支关系词汇的历史来源；
3. `SRC-BZ-ZIPING-ZHENQUAN-NLC`：已核对国家图书馆扫描本中成败救应与行运章节的方法范围；
4. `SRC-BZ-DITIAN-SUI-WIKISOURCE`：已核对体用、衰旺、月令与岁运的历史方法范围；
5. 《穷通宝鉴》：仍只登记为书目锚点，尚未安装逐日干、月支、版本核对的调候表。

“来源已核对”不等于“预测准确率得到验证”。传统文献只能说明规则属于何种历史方法，不能证明人生事件预测有效。

## 现实核对

现实核对用于检验已经冻结的候选，不用于迎合式改盘：

- 用至少两个相似周期的同期记录，而不是只回忆一次特别吻合的经历；
- 分开记录资源、承载、约束和输出，核对哪项先成为瓶颈、哪项确实缓解；
- 若资料同时支持相反路线，维持未决；
- 只有出生资料、排盘口径或规则前提发生可证实变化时才重开裁决；
- 不根据用户先告诉的结果倒推时辰、旺衰、格局或用神。

## 未闭合边界

v0.4 尚未完成：

- 人元司令、合化、墓库和空亡的流派 profile；
- 从格、专旺和化气的独立裁决；
- 经版本逐条核对的调候表；
- 财轻比重、印轻逢财、位置妥贴等需要轻重/位置的格局闭合路线；
- 把大运、流年候选条件重新跑过完整格局复合路线的动态状态机；
- 六亲与人生领域的有来源、可反驳映射；具体事件和医疗/法律/财务结果不在自动断语范围；
- 真实命例的盲审、命理师复核和跨评审一致性；
- Bazi 专用 typed reading binding（完成前 `R-BZ-005/006` 只能输出 `unresolved` claim）。

这些缺口必须通过新增精确规则、来源核验和独立测试逐项关闭，不能通过扩大提示词或增加术语掩盖。
