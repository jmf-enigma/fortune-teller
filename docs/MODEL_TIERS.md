# Model-tier decision

The complete operational contract lives in [`references/model-tiers.md`](../references/model-tiers.md).

## Release conclusion

A standard/general model is sufficient for the complete core path: route one request, collect and confirm inputs, run one local engine, explain one focused topic, summarize engine-produced sensitivity, and emit a small set of evidence cards.

A Pro/audit model is recommended, not required, when the task has more than two systems or profiles, many materially different candidates, a full conflict matrix, complete rule/source coverage, or an adversarial second pass.

The model tier never changes calculation facts, profiles, privacy gates, or safety boundaries. A higher tier improves capacity for synthesis and review; it does not improve supernatural accuracy.

## Acceptance rule

- Standard mode must be useful and complete without upgrade pressure.
- Audit mode adds traceability and breadth, not stronger destiny claims.
- When capacity is limited, narrow topics and preserve unresolved conflicts.
- Never degrade by dropping warnings, inventing sources, hand-calculating a failed engine, or hiding sensitivity.
